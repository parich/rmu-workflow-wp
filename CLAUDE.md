## Release workflow

When releasing a new version, three places must be updated together:

1. `rmu-workflow-wp.php` — the plugin header comment (`Version:`) and the `RMU_WORKFLOW_VERSION` constant
2. `src/awesome/block.json` — the `"version"` field
3. After `npm run build && npm run plugin-zip`, create a GitHub release with the `.zip` as an asset and a tag matching `v{version}`

The `RMU_Workflow_GitHub_Updater` class reads the GitHub API for the latest release and surfaces it in WordPress's plugin update screen. It caches the response in a transient for 6 hours. The tag on GitHub (`v0.2.0`) must match the version string in the plugin header (`0.2.0`) for version comparison to work.

## Architecture

### Two entry points, one widget

The plugin exposes the same interactive flowchart widget through two mechanisms:

- **Gutenberg block** (`create-block/awesome`) — registered via `wp_register_block_types_from_metadata_collection` in `init`. The block editor shows only a placeholder (`src/awesome/edit.js`); the actual widget is rendered server-side by `build/awesome/render.php`.
- **Shortcode** `[rmu_workflow dept_id="518"]` — calls `rmu_workflow_shortcode()` which includes `build/awesome/render.php` directly and manually enqueues the registered style and script.

Both paths share the same render template and the same registered assets (`rmu-workflow-style` and `rmu-workflow-view`).

### Frontend widget (`src/awesome/view.js`)

Plain vanilla JS (no framework, IIFE). The `WorkflowWidget` class:
1. Reads `data-dept-id` from the container element
2. Fetches `{apiUrl}?deptId={dept_id}` (URL set in admin or defaults to `https://workflow.rmu.ac.th/api/embed/flowcharts`)
3. Collects tags from all items and renders tag-filter pills sorted by frequency
4. Filters items client-side by active tag and debounced search input (250ms)
5. Renders a 2-column CSS grid of cards; falls back to 1 column below 600px

`window.rmuWorkflowSettings` is injected via `wp_localize_script` and carries `apiUrl` and `baseUrl`.

### Admin settings

Settings > RMU Workflow stores two options (`rmu_workflow_api_url`, `rmu_workflow_base_url`) sanitized as URLs. These override the hardcoded defaults used in `wp_localize_script`.

### Build output

`npm run build` compiles `src/awesome/` into `build/awesome/`. The `render.php` is copied verbatim by the `--webpack-copy-php` flag. `build/blocks-manifest.php` is generated by `--blocks-manifest` and consumed by `wp_register_block_types_from_metadata_collection`. Both `build/` and compiled assets are committed to the repo (required for the GitHub updater ZIP to be self-contained).

### Styling conventions

Styles use CSS custom properties scoped under `.rmu-workflow-container` with a neutral palette (`inherit` color, transparent backgrounds) so the widget matches any WordPress theme without overrides.
